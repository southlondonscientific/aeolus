# Aeolus bug audit — exhaustive multi-agent review

_Generated by a loop-until-dry workflow audit: 546 agents, 4 rounds, 5-lens adversarial verification (>=3 of 5 skeptics could not refute). Reviewed src/aeolus on branch fix/sos-circuit-breaker._

**Note:** the loop hit the 4-round safety cap WITHOUT going dry (each round still found new issues: 53, 17, 16, 15) — a deeper sweep would likely surface more. Counts include some near-duplicate findings (same root cause flagged by more than one agent).

# Aeolus Bug Audit Report

## Summary

This audit surfaced 60 verified findings across the aeolus library: **3 Critical**, **24 Important**, **18 Medium**, and **15 Low** (after merging near-duplicates). By area: the AQI/metrics layer (`metrics/`) dominates with breakpoint clamping, averaging-window/breakpoint-table mismatches, unit-conversion errors, and empty-schema issues; the visualisation layer (`viz/`) has a cluster of fixed-axis-vs-groupby crashes and silent multi-site/mixed-unit pooling; data sources (`sources/`) show recurring timezone, unit-labelling, NaN-retention, and latching-empty-cache defects; and `api.py`/`cache.py` contribute silent-filter-drop, data-capture, and cache-key/partial-cache problems. The two highest-impact themes are **out-of-range concentrations silently mapping to the worst AQI band** and **fixed-axis plotting functions crashing on incomplete temporal coverage**.

## Critical

### src/aeolus/metrics/base.py:336 — Below-range concentrations silently map to the MAXIMUM AQI band
`calculate_aqi_from_breakpoints()` returns `None` for any out-of-range concentration without distinguishing below-range from above-range; every index's `calculate()` treats `None` as "off the top" and substitutes the max AQI (EPA/China/India 500, EU 6, DAQI 10). A routine slightly-negative low-cost-sensor reading (-2.0 ug/m3 PM2.5) therefore yields "Very High"/"Hazardous", and since overall AQI is the max across pollutants, one negative reading corrupts the whole period via `aqi_summary()`/`aqi_timeseries()`.
**Fix:** distinguish below-range (return lowest band or clamp negatives to 0) from above-range (cap at max) in `calculate_aqi_from_breakpoints()`.

### src/aeolus/metrics/indices/eu_caqi.py:270 — EU CAQI breakpoint gaps clamp normal values to "Extremely Poor"
EU CAQI bands have 0.1-wide gaps (NO2 `(0,40)` then `(40.1,90)`); `calculate()` passes the raw concentration with no rounding, so a clean 40.05 ug/m3 NO2 matches no band, returns `None`, and is mapped to value 6 "Extremely Poor" — the worst category — and becomes the overall AQI driver. Reachable end-to-end via `aqi_timeseries` on real-valued rolling means for `EU_CAQI_ROADSIDE`/`EU_CAQI_BACKGROUND`.
**Fix:** make EU bands contiguous (half-open ranges) or round concentrations to 1 dp before lookup, as other indices do.

### src/aeolus/viz/prepare.py:226 — `downsample_timeseries` LTTB path corrupts all timestamps to 1970 and strips timezone
With the default `method='lttb'`, datetimes are cast via `.astype(np.int64)` (microsecond integers for aeolus's `datetime64[us, UTC]`) then rebuilt with `pd.to_datetime(x_down)` — no `unit=`, no `utc=`. pandas interprets the integers as nanoseconds, collapsing every timestamp to ~1970-01-20 and dropping tz-awareness. Any direct use of this utility on standard data yields completely wrong, tz-naive timestamps.
**Fix:** mirror `prepare_timeseries`'s correct round-trip — capture source dtype/unit and reconstruct with `pd.to_datetime(x_down, unit=dt_unit, utc=...)`, then `tz_convert` if needed.

## Important

### src/aeolus/sources/eea.py:464 — EEA keeps rows with unmapped pollutant codes as `measurand=NaN`
*(merges duplicate findings at eea.py:464 and eea.py:466)*
With the default empty `pollutants=[]` body, the EEA API returns all pollutant codes, but `POLLUTANT_CODE_MAP` covers only ~10; `map_pollutants` leaves the rest as NaN measurand and the pipeline never drops them, emitting rows with a real numeric value attached to no pollutant — corrupting any downstream groupby/mean/AQI. Every other source dropnas on measurand; EEA does not.
**Fix:** add `filter_rows(lambda df: df['measurand'].notna())` (and ideally `dropna(subset=['value'])`) after `map_pollutants`.

### src/aeolus/sources/airnow.py:376 — AirNow daily chunking duplicates the boundary hour
Each daily chunk's `endDate` is the next day at 00:00 and the next chunk's `startDate` is that same hour; the API treats both bounds as inclusive, so each day-boundary reading is returned twice with no de-duplication before `concat`, inflating counts and biasing means/data-capture over multi-day ranges.
**Fix:** make windows non-overlapping (endDate at hour 23) or `drop_duplicates(subset=['site_code','date_time','measurand'])`.

### src/aeolus/sources/airnow.py:372 — AirNow per-site fetch collapses multiple monitors onto one site_code
Each site is queried via a ~1-2km bbox and every observation returned (including other monitors in dense areas) is stamped with the single queried `site_code`, producing duplicate `(site_code, date_time, measurand)` rows with conflicting values that silently mix several real stations in any per-site stat.
**Fix:** re-derive `site_code` from each observation's own lat/lon (matching the metadata convention) or filter to the exact requested coordinates.

### src/aeolus/sources/purpleair.py:425, src/aeolus/sources/sonitus.py:242 — Naive start/end dates converted with `.timestamp()`, applying the machine's local offset
Both build query windows with `int(dt.timestamp())`; on a naive datetime this uses the machine's local timezone. Since `download()`/`resolve_dates` forward naive user dates unchanged, a non-UTC machine queries a window shifted by its local offset (e.g. 5h on US-Eastern), silently returning data for the wrong period. CI passes because tests use tz-aware UTC dates.
**Fix:** coerce naive datetimes to UTC before `.timestamp()`, ideally centrally in `resolve_dates`/dispatch.

### src/aeolus/sources/sos.py:515 & src/aeolus/sources/sonitus.py:224 — Hardcoded `units='ug/m3'` mislabels CO by ~1000x
*(SOS affects AURN-SOS/SAQN-SOS/WAQN-SOS/NI-SOS/AQE-SOS; Sonitus melts CO/gas species identically)*
Both stamp every measurand `ug/m3`. CO is reported in mg/m3 (Defra/regulatory path labels it correctly), so SOS/Sonitus CO is wrong by ~1000x. SOS already computes the correct unit per timeseries in `ts_info['uom']` but never reads it; the same station's CO is labelled differently depending on backend.
**Fix:** map units per measurand (CO→mg/m3) as `regulatory.py` does; for SOS, use the stored `ts_info['uom']`.

### src/aeolus/metrics/__init__.py:564 — `aqi_check_who` mis-converts CO in ppm/ppb, understating exceedances ~1000x
The CO branch only recognises `mg/m3`; any other unit is assumed ug/m3 and divided by 1000. CO 5 ppm (~5.7 mg/m3, an exceedance of the 4 mg/m3 AQG) becomes 0.005 mg/m3 and reports `meets_guideline=True`. The non-CO branch correctly uses `ensure_ugm3` (which handles ppm/ppb); only CO is broken.
**Fix:** convert CO via `ensure_ugm3` first, then divide by 1000.

### src/aeolus/metrics/__init__.py:566 — `aqi_check_who` crashes with AttributeError when `units` is None/NaN
The scalar path calls `row['units'].lower()` (CO) and `ensure_ugm3(..., row['units'])` (others, via `base.py:201`), so a single null-units row aborts the whole compliance report. The vectorised `ensure_ugm3_array` guards `pd.isna`; this scalar path does not.
**Fix:** guard units with `pd.notna` (default to ug/m3) and add a `pd.isna` guard at the top of `base.ensure_ugm3()`.

### src/aeolus/metrics/indices/us_epa.py:420 — US EPA O3 with `averaging_period='1h'` returns AQI 500 for normal low concentrations
The 1-hour O3 table starts at 0.125 ppm; any value below it (the vast majority of real data) matches no band, returns `None`, and is capped at AQI 500 "Hazardous" by the None-branch (0.10 ppm → 500, vs 187 on the 8h table). Same defect class as the SO2 routing bug but a distinct path.
**Fix:** when the 1h table yields None because the value is *below* its floor, fall back to the 8h table or return None rather than capping at 500.

### src/aeolus/metrics/stats.py:176 — Period-end resample bins (ME/YE/QE, M/Y/Q, W) misalign the expected-observation denominator by one period
`_expected_observations_per_bin` assumes the bin label is the period *start* and computes `bin_end = label + offset`, but end-anchored offsets label at the period *end*, so each monthly/quarterly/yearly bin is divided by the next period's length. A complete February reports `data_capture=0.935` (divided by March's 744h); marginal periods are pushed across the 75% LAQM threshold in the wrong direction, wrongly dropping or keeping means. `trend()` is unaffected (passes start-anchored freqs); `time_average()` with documented ME/YE freqs is.
**Fix:** normalise the label to the bin's left edge before adding the offset (use Period arithmetic), or pass `closed='left', label='left'` to all `resample()` calls.

### src/aeolus/api.py:583 — `measurand=` filter silently drops all 196 LMAM sites
`find_sites(..., measurand=...)`'s `_matches` only understands `measurands` as `list | None`, but LMAM's normaliser builds a comma-separated *string* (`"NO2,PM2.5"`). The string fails `isinstance(m, list)`, falls into the "unknown" branch, and since LMAM declares no `default_measurands`, returns False — silently excluding the entire LMAM network from any measurand-filtered discovery.
**Fix:** normalise LMAM measurands to `list[str]` at the source, or make `_matches` split comma-separated strings.

### src/aeolus/api.py:372 — `find_sites` bare-call fallback silently drops user filters and masks internal TypeErrors
`_fetch_network_sites` catches `TypeError` from `fetch_metadata(**kwargs)` and retries `fetch_metadata()` with no args. Regulatory networks register zero-arg fetchers, so `find_sites("AURN", location_type=...)` silently returns the full unfiltered list; genuine TypeErrors inside the fetcher/normaliser are also swallowed.
**Fix:** only fall back on an "unexpected keyword argument" TypeError (inspect the signature), apply unsupported filters post-fetch or warn; do not blanket-catch TypeError.

### src/aeolus/sources/sensor_community.py:710 — Missing/NaN archive timestamp becomes NaT and is kept
The try/except around `pd.to_datetime` never fires because `pd.to_datetime(NaN, utc=True)` returns `NaT` without raising, so rows with a valid measurand/value but null `date_time` survive into output, corrupting time-indexing/`time_average()`/capture-rate (NaT rows count toward totals but cannot be binned).
**Fix:** `if pd.isna(timestamp): continue`, or `dropna(subset=['date_time'])` before returning.

### src/aeolus/sources/purpleair.py:594 — All-invalid PurpleAir response yields a column-less DataFrame
When every channel value is invalid, `melt_to_long_format` builds `pd.DataFrame([])` (zero columns); downstream steps early-return on `df.empty` without adding columns, so the result lacks the standard 8-column schema, violating the empty-frame invariant and KeyError-ing consumers.
**Fix:** return `empty_data_frame()` when `not records`.

### src/aeolus/sources/sos.py:410 — `_get_network_mapping` latches an empty dict on transient empty build
A live `_build_station_mapping` that returns `{}` (empty RData metadata, no coordinates, empty SOS timeseries) is unconditionally stored in `_network_mappings`, and the early-return then serves `{}` forever; `get_current()`/SOS fetchers for that network silently return no data for the process lifetime with no retry or cache-clear.
**Fix:** only cache non-empty mappings so a transient empty build retries next call.

### src/aeolus/sources/eea.py:223 — EEA Samplingpoint→EoI mapping latches an empty dict on CSV-fallback / all-malformed paths
Both the `except`-branch (`_parse_csv_fallback`) and the success branch unconditionally assign `_spo_to_eoi = mapping` even when empty. Once latched empty, `_samplingpoint_to_eoi` returns raw Samplingpoint ids instead of EoI codes, so `fetch_eea_data`'s `site_code.isin(sites)` matches nothing and returns empty for all later requests. The v0.4.5 fix only protected the `csv_text is None` branch.
**Fix:** assign `_spo_to_eoi` only when the built mapping is non-empty (mirror the guarded None-branch).

### src/aeolus/cache.py:271 — Partial-success fetches cached as authoritative, latching transient per-site failures
`fetch_with_cache` caches any non-empty frame, including partial results where multi-site fetchers swallowed per-site errors with `continue`. A single transient failure on one site is baked into the Parquet cache, so that site silently appears to have no data on every future call for the same key until manual clear.
**Fix:** propagate a partial/failed signal, cache per-site rather than per-batch, or attach a TTL/completeness flag.

### src/aeolus/viz/prepare.py:324 — `prepare_timeseries` silently averages multiple sites into one line
For multi-site input (the normal `download('AURN', ['MY1','KC1'])` result), the pivot indexes only on `date_time`, so all sites' readings at each timestamp are merged via `aggfunc='mean'` — a cross-site average no user requested, unlabelled (site_name becomes "N sites"). Spans download → prepare_timeseries → plot_timeseries.
**Fix:** detect multi-site input and warn/raise, or pivot including `site_code` so each site is its own series.

### src/aeolus/viz/plots.py:758 — `plot_diurnal` silently pools multiple sites into one mean
With more than one site, `groupby('hour')['value']` pools across all sites; a roadside (90) and background (10) site collapse to a flat 50 line representing neither, titled only "N sites".
**Fix:** detect multiple sites and warn/facet/require pre-filtering.

### src/aeolus/viz/plots.py:763,913,1050,1282 — Fixed-axis temporal plots crash when coverage is incomplete
*(merges plot_diurnal:763, plot_weekly:913, plot_monthly:1050, and `_plot_diurnal_panel`:1282 in plot_time_variation; both the pandas and edge-cases duplicate findings)*
Each plots a `groupby` result (only present hours/weekdays/months) against a fixed axis (`np.arange(24)`/`(7)`/`(1,13)`) with no `reindex`, raising ValueError on any dataset not spanning all hours/days/months — i.e. nearly all short or partial downloads. The internal `_plot_weekly_panel`/`_plot_monthly_panel` already `reindex`, confirming the public paths and the diurnal panel miss it.
**Fix:** `reindex` the aggregate onto the full range (`range(24)`/`range(7)`/`range(1,13)`) before plotting and CI.

## Medium

### src/aeolus/sources/sonitus.py:219 — Sonitus parses naive Dublin-local timestamps as UTC
`convert_timestamps('date_time', utc=True)` localises naive Dublin wall-clock strings to UTC instead of converting; during Irish Summer Time a 00:00 UTC reading is stored as 01:00 UTC, so every row is off by the Irish offset, breaking alignment and hour-of-day analysis.
**Fix:** `.dt.tz_localize('Europe/Dublin').dt.tz_convert('UTC')` (after confirming the API returns local time).

### src/aeolus/sources/sonitus.py:224 — Sonitus hardcodes `units='ug/m3'` for CO and gas species
*(see merged SOS/Sonitus units entry under Important; the Medium-severity Sonitus instance is the same root cause — CO mislabelled ug/m3 vs mg/m3)*

### src/aeolus/sources/airnow.py:507 — AirNow current observations treat local `HourObserved` as UTC
`fetch_airnow_current` stamps `pd.to_datetime(f"{date_str} {hour}:00:00", utc=True)` from the local `HourObserved`, so every current reading is wrong by the site's UTC offset (5-8h) and disagrees with the historical path (which uses the `UTC` field).
**Fix:** use the observation's UTC field or convert from the reported `LocalTimeZone`.

### src/aeolus/sources/eea.py:488 — EEA `date_time` never coerced to UTC-aware datetime
The pipeline renames `Start`→`date_time` but never runs `convert_timestamps`/`pd.to_datetime(..., utc=True)`, unlike every other source, so EEA relies on the Parquet dtype (often tz-naive), violating the UTC-aware invariant and causing tz-compare errors on concat.
**Fix:** add `convert_timestamps('date_time', utc=True)` after `rename_columns`.

### src/aeolus/sources/airqo.py:558 — AirQo normaliser silently drops all non-PM pollutants (NO2/O3/SO2/CO)
`extract_pollutant_values` iterates a hardcoded `['pm2_5','pm10']`, so gas readings present in the response (and mapped in `PARAMETER_MAP`) are never extracted, melted, or returned — a silent partial result for reference-grade sites.
**Fix:** drive the loop from `PARAMETER_MAP` keys.

### src/aeolus/sources/breathe_london.py:322 — `strftime(...Z)` mislabels tz-aware non-UTC start/end as UTC
*(same pattern shared by AirQo:381-382 and EEA:568-569)*
`start_date.strftime('%Y-%m-%dT%H:%M:%SZ')` emits wall-clock components and appends a literal `Z`, so a tz-aware non-UTC datetime (e.g. Europe/London BST) is sent shifted by its offset. Harmless for naive inputs; wrong for zoned ones.
**Fix:** `astimezone(timezone.utc)` before formatting.

### src/aeolus/sources/airqo.py:381 — AirQo over-fetches whole calendar days and never trims to the requested window
The request is forced to `T00:00:00.000Z`/`T23:59:59.000Z` and the result is returned with no post-fetch date mask (unlike `regulatory.make_data_fetcher`), so sub-day or non-midnight requests silently receive up to a full extra day at each end.
**Fix:** honour the supplied time-of-day and/or filter the frame to `[start, end]`.

### src/aeolus/sources/airqo.py:405 — `fetch_airqo_data` reads only page 1 of the measurements endpoint → silently truncates history  (NEW, found while verifying the metadata fix)
The `devices/measurements/sites/{id}/historical` endpoint is paginated (`meta.limit` 30, `meta.total`, `meta.pages`, `meta.hasNextPage`). `fetch_airqo_data` reads `data.get("measurements", [])` once with no `skip`/`limit` paging, so any window with >30 records silently returns only the first 30 (verified live: a 5-day hourly window reported `total:105, pages:4` but yielded 30 rows). The measurement *shape* is unchanged (pm2_5/pm10 `{value}` dicts, `time` string, nested `siteDetails` with coords) — only the row count is truncated. **Caution before fixing:** the endpoint is flaky under rapid/parametrised querying — `limit` clamps to 80 inconsistently (100→0, 200→80, 500→0) and throttling returns an HTTP-200 silent-empty body (`measurements:[]`, `meta:null`) rather than 429, which `fetch_airqo_data`'s `success` guard treats as "no data". A fix must (a) page via `skip` at the server's own `meta.limit`, and (b) distinguish a throttled `meta:null`/empty response from a genuine empty window (retry vs. accept). Needs its own characterisation pass when the endpoint isn't throttled. **Severity: Important (silent data loss).**

### src/aeolus/sources/regulatory.py:308 — Regulatory/LAQN/LMAM pipeline never drops NaN measurement values
The shared normaliser melts dense wide grids to long without dropping `value=NaN` rows, unlike every other source, so `download('AURN', ...)` returns far more rows than real observations, inflating counts and biasing any `len()`/`value_counts` consumer.
**Fix:** add `filter_rows(lambda df: df['value'].notna())` to the normalise pipeline.

### src/aeolus/sources/sonitus.py:224 (see Important) and src/aeolus/sources/sensor_community.py:697 — see respective entries

### src/aeolus/metrics/__init__.py:603 — `aqi_check_who` returns a column-less frame on the empty path
The only return is `pd.DataFrame(results)`; when `results` stays empty (empty input, unrecognised pollutants, all-NaN, etc.) it has zero columns, dropping the documented schema and KeyError-ing consumers, inconsistent with `aqi_summary`/`aqi_timeseries`.
**Fix:** `pd.DataFrame(results, columns=_WHO_CHECK_COLUMNS)` with a fixed-column constant.

### src/aeolus/metrics/__init__.py:553 — `aqi_check_who` checks a whole-dataset mean against period-specific WHO guidelines
It takes one grand mean per (site, pollutant) and checks it against annual/24h/8h guidelines without aggregating to that period or restricting to a year: a single day of NO2 is compared to the annual guideline (spurious exceedance), multi-year input is averaged across years, and 24h/8h true short-term exceedances are hidden.
**Fix:** aggregate to the guideline's averaging period (annual mean per year; daily/8h means for short-term) before checking, or at least warn on span mismatch.

### src/aeolus/metrics/__init__.py:264 — DAQI SO2 computed from a 1-hour mean against 15-minute breakpoints
`_period_to_hours` maps SO2's `'15min'` to 1 hour, so a 1h rolling mean is looked up in the 15-minute SO2 table, smoothing away the short peaks the table is calibrated for and biasing the SO2 DAQI band low.
**Fix:** compute SO2 on the finest sub-hourly window (skip when only hourly data exists) or document the result as a lower bound.

### src/aeolus/metrics/__init__.py:270 — `aqi_summary` rolling average leaks across period boundaries
The time-based rolling mean is computed over the whole series before period labels are assigned, so a period's leading-edge readings mix in the previous period's tail; the period AQI (`valid_rolling.max()`) can therefore be driven by concentrations from period M-1, mis-attributing worst-case AQI at clean/polluted boundaries.
**Fix:** compute the rolling average within each period group (reset at boundaries) or document the boundary borrowing.

### src/aeolus/metrics/__init__.py:321 — `aqi_summary` coverage over-counts sub-hourly data
Coverage is `len(valid_raw)/expected_hours` with no resample to hourly, so a 15-minute source yields ~4 readings/hour → coverage ~4.0 clamped to 1.0, masking genuinely low coverage and defeating the low-coverage warning; coarser-than-hourly under-counts.
**Fix:** resample to the data's native/hourly frequency before computing coverage.

### src/aeolus/metrics/indices/china.py:387 — China SO2 1-hour above 800 ug/m3 jumps to AQI 500 instead of the 24h table
HJ 633-2012 switches SO2 to the 24h table above the 1-hour ceiling (AQI 200/800 ug/m3), but `calculate()` finds no band and caps at 500 "Severely Polluted"; a 900 ug/m3 1h reading (~AQI 150-200 with proper fallback) is reported as 500.
**Fix:** fall back to the 24-hour SO2 table above the 1-hour ceiling.

### src/aeolus/metrics/stats.py:241 — Monthly/weekly/quarterly/yearly `time_average` bins are right-closed and end-labeled
Bare `resample(freq)` for ME/YE/QE/W (and M/Y/Q) defaults to `closed='right', label='right'`, so a month's first reading (e.g. 1 Feb 00:00) lands in January's bin and January is labelled `2024-01-31` — violating the documented left-closed, start-labelled convention.
**Fix:** pass `closed='left', label='left'` (and prefer start-anchored offsets ME→MS etc.).

### src/aeolus/metrics/base.py:434 — `ensure_ugm3_array` truncates converted values when input is integer dtype
`result = concentrations.copy()` preserves int64 dtype, so the float-scaled ppb→ug / ppm→ug conversions are floored on assignment, corrupting AQI and summary stats for integer-valued sources. Reachable from `aqi_summary`/`aqi_timeseries`.
**Fix:** `result = np.asarray(concentrations, dtype=float).copy()`.

### src/aeolus/transforms.py:450 — `fillna(method=...)` transformer raises TypeError under pandas 3.0
*(merges the two duplicate findings at transforms.py:450)*
`DataFrame.fillna(method=...)` was removed in pandas 3.0 (the installed runtime), so the documented public `fillna(method='ffill'/'bfill')` transformer crashes with TypeError instead of filling.
**Fix:** dispatch to `df.ffill()`/`df.bfill()` explicitly.

### src/aeolus/viz/plots.py:1566 — `plot_trend` y-axis units read from the unfiltered frame's first row
`data['units'].iloc[0]` reads from the full multi-pollutant frame rather than the trend-filtered `df`, so the axis can be labelled with another pollutant's units (e.g. CO mg/m3 while plotting PM2.5 ug/m3).
**Fix:** read units from the already-filtered `df`.

### src/aeolus/viz/plots.py:662 — `plot_distribution` units label picks first row when a pollutant has mixed units
`df['units'].iloc[0]` with no uniqueness check labels mixed-unit data (e.g. CO mg/m3 vs ug/m3 across networks) with only the first row's unit while plotting unconverted values. Same latent flaw in plot_diurnal/plot_weekly/plot_monthly/plot_calendar/plot_trend.
**Fix:** check `df['units'].nunique()`; warn or convert when >1.

### src/aeolus/api.py:724 — `summarise()` data_capture inflated when gaps are regularly spaced
Frequency is inferred from the *median* inter-timestamp gap, so regularly-spaced missing data (e.g. every-other-hour) is absorbed into the inferred frequency, reporting ~100% capture when true capture is 50%.
**Fix:** infer nominal frequency from the modal/minimum positive gap, or accept the requested range/resolution as parameters.

## Low

### src/aeolus/sources/sensor_community.py:697 — SPS30 PM4 archive column (P4) silently dropped
The historical `archive_value_map` omits `'P4'`, so SPS30 PM4 measurements are dropped from downloaded history even though metadata advertises PM4 and the realtime path maps it.
**Fix:** add `'P4': 'PM4'` to `archive_value_map`.

### src/aeolus/sources/airqo.py:265 — `fetch_airqo_grids` returns the 8-col data schema on error
Success returns grid columns (`grid_id`, `name`, ...) but all three error/empty paths return `empty_data_frame()` (the standard DATA schema), so documented column access (`grids[['grid_id','name']]`) KeyErrors on the empty path.
**Fix:** return `pd.DataFrame(columns=['grid_id','name','admin_level','visibility'])` on error/empty paths.

### src/aeolus/sources/eea.py:471 — EEA `value` coerced with `errors='coerce'` but NaN values not dropped
`pd.to_numeric(..., errors='coerce')` produces NaN for unparseable concentrations that the pipeline never drops, so rows can carry both NaN value and (per the measurand bug) NaN measurand.
**Fix:** add `dropna(subset=['value'])` after `convert_value`.

### src/aeolus/sources/eea.py:510 — Empty `sites` list yields a misleading "mixed-country" warning
`_infer_country_from_sites([])` returns None, so an empty sites list triggers "Cannot infer country from mixed-country site codes" rather than a clean short-circuit.
**Fix:** early-return `empty_data_frame()` when `not sites`.

### src/aeolus/sources/openaq.py:358 — OpenAQ stamps readings with period END, violating the left-closed convention
Timestamps use `m.period.datetime_to.utc` (interval end), so each hour is labelled one bin forward relative to all other sources, misaligning joins and shifting diurnal profiles by an hour.
**Fix:** use `m.period.datetime_from.utc` (interval start).

### src/aeolus/metrics/indices/us_epa.py:429 — US EPA SO2 routes 1h-averaged data into the 24h breakpoint table
With SO2 on a 1h rolling window, `calculate()` routes purely by concentration: a 1h mean of 305-1004 ppb is scored against the 24h-only table (e.g. 400 ppb → AQI 232), producing AQI the spec defines only for 24h averages.
**Fix:** compute each sub-index from the averaging window its table is defined on; cap/flag if only 1h data is available.

### src/aeolus/metrics/indices/eu_caqi.py:331 — EU CAQI roadside/background: NaN concentration becomes "Extremely Poor"
`calculate_roadside`/`calculate_background` pass NaN into `calculate()` unfiltered → None → value 6, so a missing reading is treated as worst when taking the cross-pollutant max. Low severity as these helpers have no callers in `src/`, but they are public API.
**Fix:** `if pd.isna(conc): continue` before `calculate()`.

## Summary

This audit surfaces 62 new findings: 21 Important, 26 Medium, 15 Low. The split is 33 product bugs and 29 test-quality gaps. Product bugs cluster around three systemic weaknesses: (1) unit handling — CO and gas-species units (`mg/m3` vs `ug/m3`, `ppb`/`ppm` vs `ug/m3`) are mislabelled or mixed across SOS, Sonitus, EEA, AirNow and the metrics/viz aggregation paths; (2) missing-data sentinels and NaN/None values (AirNow -999, SOS JSON null, NaN concentrations into AQI) flowing through as real numbers or crashing; (3) duplicate-timestamp and calendar-period assumptions in the metrics layer producing silently-wrong data-capture and rolling AQI. ### src/aeolus/sources/airnow.py:433 — AirNow missing-data sentinel (-999) passed through as a real concentration
